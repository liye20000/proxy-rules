# iPhone Shadowrocket 配置指南

适用于 **iPhone 上的 Shadowrocket(小火箭)**,基于 **2.2.x** 版本界面。

> 前提:你已在 Shadowrocket 里能正常用机场节点上网(本项目不管节点)。

---

## ⚠️ 先搞清楚两个概念,别走弯路

1. **规则不在「设置」里**。底部有四个标签:**首页 / 配置 / 数据 / 设置**。本项目的规则在 **「配置」** 标签里,不是「设置」。
2. **优先用「模块」叠加,不要「替换配置」**。你机场给你的那份配置(通常叫 `default.conf`,文件较大)**里面含有你的全部节点和它自己的一堆规则**。如果你把它换成本项目那种「只有规则、没有节点」的配置,**节点会消失**。
   所以正确做法是:把本项目规则作为一个 **「模块」** 叠加上去——**只改路由、不动节点**。

### 模块和配置叠加,到底谁生效?

- **模块的优先级高于配置**:某个域名如果模块里有规则,就听模块的。
- 本项目的模块是一套 **完整的严格白名单**:**白名单域名 → 走代理(PROXY)**,并带一条 **`FINAL,DIRECT` 兜底(其余一切直连)**。由于模块优先级最高,这套规则会**主导全部路由**:
  - 白名单域名(Claude / OpenAI / GitHub / Google / YouTube …)→ **走代理**。
  - 其它所有域名 → **直连**。
- ⚠️ **这意味着会覆盖 `default.conf` 的路由**:你 `default.conf` 里原本走代理的 `apple-relay`、`copilot` 等,**会变成直连**。如果你也想让它们走代理,**把对应域名加进 `proxy-list.txt`** 即可——这正是"一处维护、处处生效"的用法。
- 节点不受影响:`default.conf` 仍然提供你的节点,只是它的**路由规则**被模块接管了。

> 如果你**不想**覆盖、只想"在现有规则上额外追加几个域名走代理",告诉维护者改用"纯叠加(只加 PROXY、不带 FINAL)"的模块即可。当前默认是**严格白名单**。

---

## 你需要的订阅 URL(模块)

把 `YOUR_USERNAME` 换成你的 GitHub 用户名:

```
https://raw.githubusercontent.com/YOUR_USERNAME/proxy-rules/main/shadowrocket.module
```

> 这个模块**只含路由规则,不含任何节点 / 密码**。规则里的 `PROXY` 表示「走你在首页选中的那个节点」——节点仍然来自你机场那份配置。

---

## 步骤 1:进入「配置 → 模块」

1. 打开 Shadowrocket,点底部 **「配置」** 标签。
2. 在上方那张卡片里点 **「模块」(`{>-}` 图标)**。

![配置-模块入口](images/sr-iphone-config-tab.png)

---

## 步骤 2:添加远程模块(粘贴 URL)

1. 在「模块」页右上角点 **「+」**。
2. 选 **「远程模块 / 来自 URL」**,把上面的 `shadowrocket.module` URL 粘进去。
3. 点 **下载 / 完成**。成功后模块列表里会出现 **「proxy-rules 白名单分流」** 并**打开(启用)**它。

> 模块是按 `#!name=` 显示的,所以这里你能看到「proxy-rules 白名单分流」这个名字。

![添加远程模块](images/sr-iphone-add-ruleset.png)

---

## 步骤 3:首页选节点 + 路由设为「配置」

1. 回到 **「首页」**,在机场节点列表里**选中一个要用的节点**(规则里的 `PROXY` 就指向它)。
2. 首页顶部的 **「全局路由」** 设为 **「配置」**(只有这个模式才会按规则分流;「代理」=全部走代理,「直连」=全部直连)。

> 你机场原来的配置(`default.conf`)仍然**提供节点**;但**路由由本模块接管**(严格白名单,见上文说明)。节点不受影响。

---

## 步骤 4:启用代理 + iOS VPN 授权

1. 回到首页,把顶部连接开关打开。
2. 首次启用时 iOS 会弹出 **VPN 配置授权**,点「允许」并用 Face ID / 密码确认。

---

## 步骤 5:验证

最简单:访问白名单网站(如 `claude.ai` / `youtube.com`)能打开;访问国内网站(如 `baidu.com`)正常。想**精确看每个域名走代理还是直连**,用下面两种方法。

### 方法 A:「测试规则」——查某域名走代理还是直连(推荐)

不用真的访问,直接拿当前生效的规则算结果,最干净:

1. 底部 **「配置」** 标签 → 点卡片里的 **「测试规则」**。
2. 在输入框输入一个域名(如 `claude.ai`)→ 回车。
3. 它会显示**命中了哪条规则**及最终策略:**PROXY(代理)/ DIRECT(直连)/ REJECT(拦截)**。

逐个验证:
- `claude.ai` / `youtube.com` / `github.com` → 应为 **PROXY**。
- `baidu.com` / 任意不在白名单的域名 → 应为 **DIRECT**(严格白名单,其余全部直连)。

> 如果白名单域名测出来是 DIRECT,说明模块没生效:检查模块开关是否打开、是否刷新到最新、「全局路由」是否为「配置」。见 [troubleshooting.md](troubleshooting.md)。

### 方法 B:「数据」——看实时连接走了什么

1. 底部 **「数据」** 标签 → 看 **「连接 / Connections」** 实时列表。
2. 每条连接显示**目标地址**与走的**策略(代理 / 直连)**;点开某条可看命中的规则与出站节点。
3. 想验证某网站,就在浏览器打开它,再回「数据」里看那条连接走的是不是 `PROXY`。

---

## 更新规则

之后你在 GitHub 改了 `proxy-list.txt`,Actions 会自动重新生成 `shadowrocket.module`。手机端在 **「配置 → 模块」** 里对 `proxy-rules` 这条做一次 **更新 / 刷新**(下拉刷新或点更新),再断开重连一次即可。

---

## 备选:用整份配置替换(一般用不到)

仅当你的**节点是通过「服务器订阅」单独添加**的(而不是机场给的整份配置),才可以用替换式配置:

- URL:`https://raw.githubusercontent.com/YOUR_USERNAME/proxy-rules/main/shadowrocket.conf`
- 在 **「配置」** 页右上角 **「+」** 添加该 URL → 下载 → 在列表里**点选它**(出现 ✓ 表示正在使用)。
- ⚠️ 注意:这会成为生效配置;若你的节点原本在别的配置里,会丢节点。**拿不准就用上面的「模块」方式。**

遇到问题见 [troubleshooting.md](troubleshooting.md)。
